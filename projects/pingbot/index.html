About

PINGBOT is a small, working ping bot for Meshtastic. A Meshtastic radio is plugged into a Linux machine over USB, and the bot listens for text messages on the mesh. Send it ping and it answers with an automated PONG that includes the signal quality it received your message with (RSSI and SNR).

It also answers help and info, reports system and mesh status, lists the nodes it heard last, rolls dice, tells jokes — and has a few easter eggs, including a hidden text adventure for those who go looking.

Features

USB auto-detect

Finds the radio by itself, via /dev/serial/by-id with fallback to ttyACM* and ttyUSB*.

Auto-reconnect

If the radio drops out, the bot retries with exponential backoff, from 5 s up to 60 s, until it is back.

Delivery confirmation

Replies request an ACK, and the log shows whether the mesh confirmed delivery or why it failed.

Private replies

Every answer goes back as a direct message, including PKI-encrypted DMs.

Signal diagnostics

ping returns the RSSI and SNR of your message as the bot received it.

Monitoring and stats

System status, mesh node count, last-heard nodes and usage statistics, all by text command.

Rotating logs

Tagged console and file logging, rotated at 2 MB with five backups.

Lightweight

One Python file, minimal dependencies, and bad packets are logged instead of crashing the bot.

How it works

  1. Connect. The bot builds a list of serial ports, tries them in turn, and reads its own node ID from the radio. If nothing connects, it keeps retrying.
  2. Listen. It subscribes to incoming mesh packets and handles text messages only. Its own messages are ignored, and other packet types are just counted for the stats.
  3. Route. Each message goes to the command handler, unless that sender has a game running, in which case the game takes it.
  4. Reply. The answer is sent as a direct message back to the sender, even if the command came in on a channel. This keeps PKI-encrypted DMs decoding correctly on the other end.
  5. Confirm. Each reply asks for an ACK. The log records whether the mesh confirmed it or reported a failure reason.
  6. Recover. A lost connection or a serial error during sending closes the link and runs the connect loop again.

Install

Needs Python 3.10+, Linux (Debian, Ubuntu or Raspberry Pi OS) and a Meshtastic radio connected over USB serial. There is no TCP/network transport.

# get the code
git clone https://github.com/why0712/meshtastic.ping.bot.git
cd meshtastic.ping.bot
pip install -r requirements.txt

# if the serial port is not accessible
sudo usermod -aG dialout $USER
sudo systemctl stop ModemManager

# run it
python3 pingbot.py

Logging

Output goes to the console and to a rotating meshbot.log next to the script.

[RX] packet received
[CMD] command parsed
[TX] reply transmitted
[ACK] delivered, or FAILED with a reason
[GAME] simulation event
[SYSTEM] startup, connect, reconnect
[ERROR] system error

Good to know

  • Replies to a peer with a stale cached public key can fail with a NO_CHANNEL routing error.
  • The CPU temperature in monitor is read the Raspberry Pi way, so it may be missing on other hardware.
  • There is no weather command on purpose, because it would need internet access.
  • There is no built-in rate limit, so be considerate with the airtime.
