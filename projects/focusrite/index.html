About this project

Setup and troubleshooting notes for Focusrite Scarlett USB interfaces on Debian 13 "Trixie": a Scarlett 2i2 (1st Gen) and a Scarlett 8i6, with PipeWire and plain ALSA. Unofficial: it describes what worked on my machines. Created by 9A3WHY with the assistance of Claude, an AI assistant by Anthropic. Source and PDF guides: github.com/why0712/focusrite.scarlett.pro.audio.trixie

In short

  • Both interfaces are USB class compliant: the standard kernel driver snd_usb_audio is all you need
  • No proprietary Focusrite Linux driver, no Focusrite Control, no boot-time driver reload script
  • For the 2i2 Gen 1 the kernel version matters: a stock kernel can give distorted or silent audio
  • For the 8i6 the Pro Audio profile removed the lag when playback starts after silence

Read this first. The 8i6 and the 2i2 are different interfaces. Do not copy card numbers, channel counts, USB IDs, profiles or ALSA definitions from one model to the other. Always check the real hardware with lsusb, aplay -l and /proc/asound/cards.

1. Recommended desktop setup

For a normal Debian GNOME desktop use the kernel USB-audio driver with PipeWire, WirePlumber and the PipeWire PulseAudio layer, plus ALSA utilities for diagnostics.

shell
sudo apt update
sudo apt install alsa-utils pipewire pipewire-audio pipewire-pulse pipewire-alsa wireplumber pavucontrol

Check the services and the audio graph:

shell
systemctl --user status pipewire
systemctl --user status pipewire-pulse
systemctl --user status wireplumber
wpctl status
pactl info | grep "Server Name"

2. Identify the hardware

Connect the interface directly to a USB port and run:

shell
lsusb
aplay -l
arecord -l
cat /proc/asound/cards
lsmod | grep snd_usb_audio
cat /proc/asound/card*/stream0
dmesg | grep -i -E 'usb|snd|scarlett|focusrite'

stream0 shows the formats and sample rates this particular unit offers. Pick a rate from that list, never one copied from another model. If the driver is missing, sudo modprobe snd_usb_audio loads it.

3. If the device is not detected

Work through these in order:

  1. Try another USB port.
  2. Avoid an unpowered USB hub.
  3. Try another known-good USB cable.
  4. Check lsusb and dmesg.
  5. Check that snd_usb_audio is loaded.
  6. Reboot after a kernel update.
  7. Check aplay -l and arecord -l again.

If lsusb sees the device but ALSA does not, look at the kernel and driver layer.

4. Direct ALSA test

Before debugging PipeWire, prove that ALSA can talk to the hardware. Replace X,Y with the numbers from aplay -l.

shell
speaker-test -D hw:X,Y -c 2 -r 48000 -f S16_LE
aplay -v /usr/share/sounds/alsa/Front_Center.wav
arecord -f S32_LE -r 48000 -c 2 test.wav -d 5
aplay test.wav

5. "Device or resource busy"

Find out who owns the sound device:

shell
lsof /dev/snd/*
sudo fuser -v /dev/snd/*

PipeWire may legitimately own the device during normal desktop use. For a temporary direct ALSA test, stop the user audio services and start them again afterwards:

shell
systemctl --user stop pipewire pipewire-pulse wireplumber
# run the ALSA test here
systemctl --user start pipewire pipewire-pulse wireplumber

Do not add boot-time scripts that unload and reload snd_usb_audio. The kernel loads it by itself.

6. Pick the Scarlett in PipeWire

The Scarlett should appear under Audio devices in wpctl status. Set the default output with the sink ID shown there:

shell
wpctl status
wpctl set-default ID

pavucontrol shows output and input devices, application streams, volume and the selected profile.

7. Scarlett 8i6: playback lag and the Pro Audio profile

The 8i6 first appeared through an ACP-generated "Analog Surround 2.1" profile and had a delay when audio started after silence. Switching the card to Pro Audio made pause, resume and volume changes immediate.

ItemWorking observation
Audio serverPipeWire 1.4.2 with PulseAudio compatibility
Session managerWirePlumber 1.4.2
InterfaceFocusrite Scarlett 8i6 USB (1235:8213)
USB autosuspendruled out
ProfilePro Audio
HDA power savepower_save=0
Sink suspendsession.suspend-timeout-seconds = 0

Check and set the profile (use the card name from pactl list cards short):

shell
pactl list cards | grep -A1 'Active Profile'
pactl set-card-profile CARD_NAME pro-audio

In Pro Audio mode the 8i6 is shown as a six-channel interface (AUX0 to AUX5); a stereo stream lands on the first pair. The WirePlumber rule that stops ALSA sinks from suspending:

ini
monitor.alsa.rules = [
  {
    matches = [
      {
        node.name = "~alsa_.*"
      }
    ]
    actions = {
      update-props = {
        session.suspend-timeout-seconds = 0
      }
    }
  }
]

Keep it as a deliberate setting, do not copy it blindly to every system. HDA power saving was also switched off during the 8i6 work (options snd_hda_intel power_save=0); this is not necessarily needed for other models.

8. Scarlett 2i2 Gen 1: the kernel issue

The 1st Gen 2i2 has a kernel specific problem. The affected USB IDs include:

1235:8006
1235:8016

Upstream Linux has fixes for a wrong USB interface setup that can show up as distorted or silent audio. Check the ID and the running kernel:

shell
lsusb
uname -r

Debian Trixie's stock kernel is in the 6.12 series; Trixie backports provides newer ones (6.18 at the time of writing). If the stock kernel gives distorted or silent audio on the 2i2 Gen 1, use a current backports kernel. Enable the repository:

shell
sudo tee /etc/apt/sources.list.d/trixie-backports.sources <<'EOT'
Types: deb
URIs: http://deb.debian.org/debian
Suites: trixie-backports
Components: main
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
EOT

Install the kernel and reboot:

shell
sudo apt update
sudo apt install -t trixie-backports linux-image-amd64 linux-headers-amd64
sudo reboot

Verify with uname -r, and keep the previous kernel installed until the 2i2 is confirmed working. If your current kernel already behaves, do not change it.

9. Scarlett 2i2 Gen 1: what you do NOT need

  • No proprietary Focusrite Linux driver (Focusrite does not officially support Linux; the 1st Gen is class compliant)
  • No Focusrite Control or MixControl
  • No boot-time snd_usb_audio reload script
  • No alsa-scarlett-gui: the small 1st Gen models (Solo, 2i2, 2i4) have no software controls

10. Optional ~/.asoundrc

Only create a custom ALSA device if an application really needs one. First find the card number with cat /proc/asound/cards and aplay -L. A stereo 2i2 example, saved as ~/.asoundrc (this is ALSA syntax, do not paste it into Bash):

ini
pcm.scarlett {
  type plug
  slave {
    pcm "hw:0,0"
    rate 48000
    format S32_LE
    channels 2
  }
}

pcm.!default pcm.scarlett

ctl.!default {
  type hw
  card 0
}

Test it:

shell
aplay -D scarlett -v /usr/share/sounds/alsa/Front_Center.wav

If PipeWire is your desktop audio server you normally do not need this.

11. Optional 96 kHz ALSA device

Use it only if cat /proc/asound/card*/stream0 confirms 96 kHz on your unit. For the 2i2:

ini
pcm.scarlett96 {
  type plug
  slave {
    pcm "hw:0,0"
    rate 96000
    format S32_LE
    channels 2
  }
}
shell
aplay -D scarlett96 -v /usr/share/sounds/alsa/Front_Center.wav

The 8i6 ALSA-only setup used 96 kHz with six playback and ten capture channels (device hw:0, channels 6 and 10); the full definition is in the 8i6 PDF in the repository.

12. Diagnostic bundle

Run this when you ask for help. It only prints information:

shell
echo '=== Kernel ==='; uname -r
echo '=== Debian ==='; cat /etc/debian_version
echo '=== USB ==='; lsusb | grep -i -E 'focusrite|scarlett'
echo '=== ALSA cards ==='; cat /proc/asound/cards
echo '=== Playback ==='; aplay -l
echo '=== Capture ==='; arecord -l
echo '=== Driver ==='; lsmod | grep snd_usb_audio
echo '=== Stream capabilities ==='; cat /proc/asound/card*/stream0
echo '=== Kernel messages ==='; dmesg | grep -i -E 'usb|snd|scarlett|focusrite' | tail -100
echo '=== PipeWire ==='; wpctl status
echo '=== PipeWire services ==='; systemctl --user --no-pager status pipewire pipewire-pulse wireplumber
echo '=== Pulse compatibility ==='; pactl info | grep 'Server Name'
echo '=== Device ownership ==='; lsof /dev/snd/* 2>/dev/null || true

Save it as diagnostics.sh and run bash diagnostics.sh > scarlett-diagnostics.txt 2>&1.

13. Troubleshooting order

Always go from the bottom up:

  1. USB: lsusb. If this fails, do not touch PipeWire yet.
  2. Kernel and driver: lsmod | grep snd_usb_audio and dmesg.
  3. ALSA: aplay -l, arecord -l, stream0.
  4. Direct playback: speaker-test -D hw:X,Y -c 2 -r 48000 -f S16_LE.
  5. PipeWire: wpctl status and the three user services.
  6. Applications: only now look at Firefox, Chromium, GNOME and so on.

14. Quick recovery checklist

If the Scarlett suddenly stops working:

shell
lsusb
aplay -l
arecord -l
lsmod | grep snd_usb_audio
cat /proc/asound/cards
cat /proc/asound/card*/stream0
wpctl status
systemctl --user status pipewire pipewire-pulse wireplumber
lsof /dev/snd/*
  • USB missing: cable, port, hub, kernel.
  • USB there but no ALSA card: snd_usb_audio and the kernel.
  • ALSA works but desktop audio does not: PipeWire and WirePlumber.
  • "Busy": find the owner with lsof or fuser.
  • 2i2 Gen 1 distorted or silent: check the USB ID and kernel version before changing anything else.

15. Known open issue

On the 8i6, live streams in Firefox (live radio, live YouTube) could sound robotic or crackly, while normal videos and Chromium were clean. PipeWire showed no errors and sample-rate unification did not help. This is unresolved, it is not a 2i2 issue, and no fix is claimed here.
